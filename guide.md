## 1. Why add AI work

How often US job descriptions mentioned GenAI work in 2024 and 2026, for eight roles. Use it to decide how much AI work your portfolio should show.

| Role | 2024 | 2026 |
|---|---|---|
| Data Scientist | 13.7% (144 of 1,051) | 42.7% (795 of 1,864) |
| Software Engineer | 6.4% (68 of 1,068) | 41.4% (580 of 1,400) |
| Product Manager | 5.3% (40 of 755) | 33.1% (391 of 1,182) |
| Engineering Manager | 3.7% (18 of 489) | 29.8% (216 of 725) |
| DevOps / SRE | 1.3% (21 of 1,562) | 27.0% (225 of 832) |
| Security Engineer | 1.0% (3 of 303) | 23.2% (308 of 1,327) |
| QA / SDET | 0.3% (4 of 1,259) | 21.7% (270 of 1,243) |
| Technical Program Manager | 4.3% (29 of 679) | 20.7% (81 of 391) |

Every one of these roles moved. A portfolio with one working AI project, close to your own field, shows you can do that work.

*Source: Interview Kickstart analysis of US job postings (2024 workbooks; LinkedIn pulls in July and October 2026).
"GenAI work" means LLMs, AI agents, RAG, prompt engineering and AI coding tools. A posting counts if it mentions them anywhere;
most mentions are preferred skills or context, not requirements. In 2024 only 3 security and 4 QA postings mentioned GenAI work.*

## 4. Your domain × AI project

A way to pick one AI project from work you already know. Use it to choose and scope the featured project on your homepage.

Skip the tutorial projects everyone builds. Build a small tool for a task from your own work, using public or synthetic data.
Knowing a niche problem well is an advantage: few people can build for it.

**Your domain** (a task you know well that is slow, repetitive or error-prone) **× an AI pattern = your project**:
small, working and measured. It becomes your featured project.

| Pattern | What it does |
|---|---|
| Extract | Pull structured fields out of messy documents |
| Ask | Answer questions from documents, with sources |
| Triage | Sort and prioritize items, with a reason |
| Draft | Write a first version for a person to review |
| Check | Review a document or config against rules |
| Act | An agent that runs several steps with tools |

### Pick your background

Starting points only. Swap in a task you've done yourself; that's what makes the project yours.

| Background | Project | Pattern | Data | How to measure |
|---|---|---|---|---|
| Healthcare | Prior-authorization letter drafter | Draft | Synthea synthetic patient records | 20 cases checked against a payer's required-fields list |
| | Drug label Q&A with citations | Ask | openFDA drug labels | 30 test questions: % correct, % with the right citation |
| Finance & insurance | Consumer complaint router | Triage | CFPB Consumer Complaint Database (already labeled) | Accuracy against the existing labels on 200 complaints |
| | 10-K risk-factor change tracker | Check | SEC EDGAR filings | Changes found vs. your own read of 10 companies |
| SAP & ERP | Configuration and process assistant | Ask | Public product documentation and your own notes | 25 questions you've been asked before |
| | Data migration mapping checker | Check | A synthetic mapping sheet with errors you plant | Planted errors caught vs. false alarms |
| Security | Vulnerability triage for a tech stack | Triage | NVD and the CISA Known Exploited Vulnerabilities catalog | Are known-exploited CVEs ranked first? |
| | Phishing email explainer | Check | Public labeled phishing datasets | Precision and recall on 200 labeled emails |
| DevOps & cloud | Runbook agent | Act | A local Kubernetes cluster (kind or minikube) with faults you plant | Planted faults diagnosed correctly; no write commands run |
| | Incident summary drafter | Draft | Loghub public log datasets | Minutes to a first draft; reviewer rating on 10 incidents |
| QA & testing | Test cases from user stories | Draft | Public issues from an open-source project | % of acceptance criteria covered |
| | Flaky test classifier | Triage | Public CI logs from open-source repositories | Accuracy on 50 failures you labeled |
| Data & BI | Ask-your-data with SQL that runs | Ask | A public dataset, such as the Olist e-commerce data | 30 questions: % whose result matches your own SQL |
| | KPI change explainer | Draft | Any public time-series dataset | Its explanations vs. yours over 10 weeks |
| Embedded & hardware | Datasheet Q&A | Ask | Manufacturers' public datasheets | 25 questions: % correct with the right page |
| | Telemetry anomaly explainer | Triage | Public sensor datasets | Anomalies found vs. labeled anomalies |
| Product & program | Feedback theme finder | Extract | Public app-review datasets | Agreement with your own tagging of 100 reviews |
| | Product spec reviewer | Check | Your own sample specs | Gaps found vs. a senior PM's review |
| Engineering leadership | Postmortem pattern finder | Extract | Public postmortem collections | Themes across 50 postmortems vs. your own read |
| | Design-doc reviewer | Check | Public design docs and RFCs from open-source projects | Issues it raises that you would raise too |
| Supply chain & operations | Supplier email to order update | Extract | Synthetic supplier emails you generate | Field accuracy on 50 emails |
| | Late-delivery explainer | Ask | The Olist e-commerce dataset | Its answers checked against the data for 20 orders |

### Build it in a weekend

1. **Pick one task** from your own work: one input, one output.
2. **Use safe data:** public or synthetic. Never your employer's, a customer's or a patient's.
3. **Build the smallest version** with your coding assistant, in your class project.
4. **Measure it:** 20 to 30 test cases you check by hand. Note accuracy, time and cost per run.
5. **Write it up** as a case study (see Upgrade 2).
6. **Feature it** at the top of your homepage and post about it on LinkedIn.

### What makes it convincing

- Numbers: how many test cases, accuracy, cost per run, time saved
- One case it gets wrong, and what you changed
- A live demo or a 60-second video
- How you built it: the coding assistant, the model, what you checked by hand
- Answers that cite their sources
- A plain statement that the data is public or synthetic

### Prompt for your coding assistant

```text
I want one AI portfolio project that combines my domain with AI.
My background: [ROLE, INDUSTRY, YEARS]. Tasks I know well: [2-3 TASKS]. Target role: [ROLE].
1. Suggest five project ideas. For each: the task, the AI pattern (extract, ask, triage, draft, check or act), a public or synthetic dataset I can legally use, and how I'd measure that it works.
2. Rank them by what a hiring manager for [ROLE] would find most convincing.
3. For the top one, list the smallest version I can build in a weekend inside this Next.js project.
Don't suggest using my employer's or any customer's data.
```

## 5. Eight upgrades

Changes to your class site, in order of impact. Each one says what to do and why. The steps and the prompt for your coding assistant are folded below each one.

### Upgrade 1: Lead with your story · 1–2 hours · free

**Do this:** rewrite the top of your homepage. Show the role you want, one line of proof, where you're based (and remote, hybrid or on-site), and two buttons: **Download resume** and **Book 15 minutes**.
**Why:** someone skimming your site wants to know what role you want, what you've done and how to reach you. Answer that before the first scroll.

**Pick the one that fits you**

| You are | Lead with |
|---|---|
| Moving into AI | Your domain × AI project |
| Between roles | Target role in the headline, "Available now", resume and booking link |
| Senior IC | Three or four case studies with scale and numbers, recent work first |
| Leader | Teams led, decisions made and what changed; writing or talks |
| Back from a break | Recent courses and projects with dates, and one honest line about the break |

<details>
<summary>Steps</summary>

1. **Headline:** your name and target role, in words a recruiter would search ("Senior Data Engineer", not "Data Wrangler").
2. **Proof:** one line with a number ("Cut pipeline costs 40% at a 2,000-person fintech").
3. **"Work with me" section:** roles you're targeting; years, domains, stack and certifications; a booking link ([Cal.com](https://cal.com/pricing) has a free plan for individuals; Google Calendar appointment schedules also work); two or three LinkedIn recommendations, with permission.
4. **Resume PDF:** save it in `public/` as `firstname-lastname-resume.pdf`. Remove your home address, and your phone number unless you want calls. Keep it consistent with the site.
</details>

<details>
<summary>Prompts for your coding assistant</summary>

```text
Read data/profile.json and src/app/page.tsx. I'm targeting [ROLE] roles in the US.
My strongest proof is [ONE PROJECT OR RESULT].
Suggest a one-line headline and a two-sentence pitch that lead with that proof.
Give me three options. Don't change any files yet.
```

```text
Rework the top of my homepage for recruiters. Target role: [ROLE].
Location and work style: [CITY, remote/hybrid, open to relocation?].
1. Hero: my name, the role, one line of proof from data/profile.json,
   and two buttons: "Download resume" (public/[file].pdf) and "[Book a call / Email me]".
2. Add a "Work with me" section: roles I'm targeting, quick facts
   (years, domains, stack), and my booking link [URL].
3. Keep all text in data/profile.json, not hard-coded in the page.
Check it at 375px and 1440px wide and tell me what you changed.
```
</details>

### Upgrade 2: Turn projects into case studies · 1–2 hours each · free

**Do this:** give your two best projects their own page, starting with your domain × AI project.
**Why:** a project card says what you built. A case study shows how you think, which is what a hiring manager is judging.

**Every case study has six parts:** 1 Problem (one or two sentences anyone can follow) · 2 Your role (say "I") ·
3 Approach (two or three key decisions and why) · 4 Result (a number) · 5 What's next · 6 Evidence (screenshots, a short video, GitHub, a live link).

<details>
<summary>Steps</summary>

1. **Start with the class project.** The Job Fit Analyzer, Cover Letter Generator and Interview Prep tools make a real case study: a Next.js app with login, server-side model calls and a provider-neutral AI helper. Add a short screen recording; keep the tools themselves private.
2. **Work you can't share** (it belongs to an employer): describe the problem and your decisions in general terms, leave out the company's numbers, names and code, and say "Details changed to protect client data."
</details>

<details>
<summary>Prompt for your coding assistant</summary>

```text
Add case-study pages for my projects. Use the projects in data/profile.json.
1. Create /projects/[slug] pages. If I'm on GitHub Pages, use
   generateStaticParams so it still exports as static files.
2. Each page has: Problem, My role, Approach, Result, What I'd do next, Evidence.
   Add those fields to data/profile.json; leave them empty where I haven't
   given you facts, and don't invent results or numbers.
3. Link each homepage project card to its page.
Then ask me five questions to fill in the first case study.
```
</details>

### Upgrade 3: Use your own domain name · 30 minutes · about $10–12 a year

**Do this:** buy `firstnamelastname.com` (or `.dev` or `.me` if it's taken) and point it at your site. Avoid hyphens and numbers.
**Why:** `yourname.com` on a resume looks deliberate, and the link stays the same if you later move from GitHub Pages to Vercel.

**Pick one registrar** (a .com, per year)

| Registrar | Price | Best for |
|---|---|---|
| [Cloudflare Registrar](https://www.cloudflare.com/products/registrar/) | About $10.50, sold at cost; free email forwarding | Lowest price |
| [Porkbun](https://porkbun.com/) | About $11, the same price every year | Simplest dashboard |
| [Vercel Domains](https://vercel.com/domains) | Shown at checkout; connects itself | Easiest on Vercel |
| Namecheap | About $11 the first year, then about $18.70 | Watch the renewal |

<details>
<summary>Steps</summary>

**On Vercel** ([Vercel guide](https://vercel.com/docs/domains/working-with-domains/add-a-domain)):
1. Project → Settings → Domains → Add Domain. Add `yourname.com` and `www.yourname.com`.
2. At your registrar, add the A and CNAME records Vercel shows for your project.

**On GitHub Pages** ([GitHub guide](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site)):
1. Repository → Settings → Pages → Custom domain. Enter it and Save *before* you add DNS records.
2. At your registrar, add four A records for the domain: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`.
3. Add a CNAME record for `www` pointing to `USERNAME.github.io`.
4. When the site loads, tick Enforce HTTPS. Because you publish with GitHub Actions, no `CNAME` file is needed.

**The one thing that breaks:** the class Pages version set `basePath: "/portfolio"`. On your own domain, set it to `""`, or styles and links break.

DNS changes can take up to 24 hours, usually minutes. Optional: forward `hello@yourname.com` to your Gmail for free with
[Cloudflare Email Routing](https://www.cloudflare.com/products/email-routing/) or Porkbun. It receives mail only.
</details>

<details>
<summary>Prompt for your coding assistant</summary>

```text
I bought [yourname.com] and I host my public portfolio on [GitHub Pages / Vercel].
1. Check next.config.ts. If I'm on GitHub Pages with a custom domain,
   basePath must be "". Fix it and any links that assumed /[repo-name].
2. List the exact DNS records I need to add at [registrar], and where
   in their dashboard. Don't guess values that my host shows me; tell me
   where to read them.
3. After I confirm the records are added, help me verify with dig
   (Mac) or Resolve-DnsName (Windows) and check https:// works.
```
</details>

### Upgrade 4: Make shared links look right · 30 minutes · free

**Do this:** add a page title, a description, a share image and a small site icon. Test the preview on LinkedIn, then tell Google about your site.
**Why:** when you share your link on LinkedIn, Slack or email, people see a preview card first. Without these, it shows as a bare URL.

<details>
<summary>Steps</summary>

1. **Title and description** in `src/app/layout.tsx`: `Your Name | Target Role` and your one-line pitch.
2. **Share image:** `opengraph-image.png`, 1200×630, in `src/app/`. A static file works on GitHub Pages and Vercel.
3. **Site icon:** `src/app/icon.png` or `icon.svg`.
4. **Sitemap:** `sitemap.ts` and `robots.ts` in `src/app/`.
5. **Structured data:** JSON-LD marking your homepage as a [ProfilePage](https://developers.google.com/search/docs/appearance/structured-data/profile-page) about a Person, linked to your LinkedIn and GitHub.
6. **Test** in [LinkedIn Post Inspector](https://www.linkedin.com/post-inspector/). Run it again after each change; posts already published keep their old preview.
7. **Tell Google** in [Search Console](https://search.google.com/search-console): add your domain, verify it with the DNS record it gives you, and submit `/sitemap.xml`.

Reference: Next.js [Metadata and OG images](https://nextjs.org/docs/app/getting-started/metadata-and-og-images).
</details>

<details>
<summary>Prompt for your coding assistant</summary>

```text
Add SEO and sharing metadata to my portfolio. My site is [https://yourname.com],
hosted on [GitHub Pages / Vercel].
1. In src/app/layout.tsx set title "[Name] | [Role]", a description from my pitch
   in data/profile.json, and metadataBase.
2. Create a 1200x630 opengraph-image.png in src/app with my name and role
   (a static file, so it works with static export). Use my photo if I have one in public/.
3. Add an icon, sitemap.ts and robots.ts. Keep them static if I use GitHub Pages.
4. Add JSON-LD for a ProfilePage whose mainEntity is a Person with name, jobTitle,
   image, and sameAs links to my LinkedIn and GitHub from data/profile.json.
Then build, and show me the <head> tags from the built homepage.
```
</details>

### Upgrade 5: Link your site from LinkedIn · 30 minutes · free

**Do this:** add your site to LinkedIn's Contact info and Featured section, end your About with it, and post about what you built.
**Why:** recruiters look you up on LinkedIn. Your site should be one click from your profile, with the preview from Upgrade 4.

<details>
<summary>Steps</summary>

1. **Contact info → Add website.** You can add up to three. Choose type Portfolio, or Other to write your own label. [LinkedIn help](https://www.linkedin.com/help/linkedin/answer/a548010)

3. **About:** end with "Projects and case studies: yourname.com".
4. **Projects** on each relevant job: link the case study.
5. **Post** a short note on what you built and what you learned.
6. **Custom button** ("Visit my website"): only for some Premium Business, Sales Navigator and Recruiter Lite subscribers. [LinkedIn help](https://www.linkedin.com/help/linkedin/answer/a1484520)

**Also add it to:** your resume header, your GitHub profile and profile README, your email signature, and the Website field on job applications.
</details>

<details>
<summary>Prompt for your coding assistant</summary>

```text
Write three versions of a short LinkedIn post announcing my portfolio at
[yourname.com]. I'm targeting [ROLE]. Mention one thing I built with AI and

```

### Upgrade 7: Make it look like you · 1–3 hours · free

**Do this:** choose one accent color and a pair of fonts, add dark mode and a clear headshot, and check the site on your phone.
**Why:** the class template is plain on purpose. A few design choices make it yours without pulling attention from the content.

**Pick one:** restyle what you have (recommended) · [Portfolio Starter Kit](https://vercel.com/templates/next.js/portfolio-starter-kit) (Vercel; blog, sitemap and share images built in) ·
[Magic UI portfolio](https://github.com/dillionverma/portfolio) (MIT; all content in one file) · [more templates](https://vercel.com/templates/portfolio) (check each license).

<details>
<summary>Steps</summary>

1. Pick one accent color plus neutrals that pass contrast checks.
2. Load a heading and a body font with `next/font`. Inter, Geist and IBM Plex are safe choices.
3. Add dark mode that follows the visitor's system setting, with a toggle.
